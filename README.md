# VeloTrack Pro (Cycling)

专为城市通勤与长途巡航打造的自行车运动学遥测、地图可视化与自适应训练决策工作台。

---

## 为什么写这个项目

在广州、深圳等高密度城市骑行时，现有的码表与运动社区往往有几个绕不开的痛点：

1. **等红灯把均速拉垮**：一趟 15 公里的夜骑，可能有 20% 的时间被路口红绿灯切碎。常规软件只给一个综合均速，很难看清自己真实的巡航节奏到底是多少。
2. **小轮车与起步伤膝**：折叠车或特定齿比配置（例如大行 P8 常见的 46T 牙盘配 11-28T 飞轮）在频繁红绿灯起步时，如果挂在大飞轮死踩起步，对半月板的瞬间剪切负荷极大。通用 AI 教练不知道你的车配了什么牙盘，给不出带齿比和踏频的具体防护建议。
3. **底图坐标系偏移**：国内矢量地图（GCJ-02 火星坐标）和国际开源等高线地图（OpenTopoMap / WGS-84）存在数百米系统性偏差，轨迹画在等高线图上经常偏到几百米外的水沟或居民楼里。
4. **图表假波形与死数据**：很多分析页面为了图表好看，用正弦波平滑出假的速度海拔线，红绿灯停顿位置也是写死的，无法真正复盘某个特定路口的通行耗时。

VeloTrack Pro 从底层轨迹点位数学解算开始重构，把真实 GPS 采样点位、机械齿比动力学模型、多底图坐标自适应与车手伤病记忆流打通，做成一个开箱即用的专业工作台。

---

## 核心特性

### 1. 双均速体系与有效做功透明化
- **停表骑行均速 (Moving Avg Speed)**：扣除全部静止与等红灯时间，只计算踩踏做功阶段的巡航均速与峰值冲刺速。
- **综合总均速 (Elapsed Avg Speed)**：门到门全历时计算，直观展示停顿耗时（如 `停顿 12.6分 / 33%`），量化城市路况对体能节奏的影响。

### 2. 真实 GPS 遥测微观动力学引擎
- 彻底废除前端合成正弦波，直接解析轨迹中的原始经纬度序列，按相邻球面步长位移 $\Delta d_i$ 还原瞬时时速与起伏海拔。
- 自动聚类静止点（位移 $< 3.2\text{m}$），将真实停顿时间分配至实际地理坐标，在地图上原位标记呼吸光晕徽标。

### 3. 速度海拔图与地图双向毫秒级联动
- **连续光标双向滑动**：鼠标在右侧折线图上左右滑动，左侧地图探针沿真实道路滑移并弹出瞬时工况；鼠标在地图线路上滑动，右侧图表逆向同步显示十字游标与数据 Tooltip。
- **路口停顿与里程碑互锁**：点击地图上的 ⏸️ 停顿标记，图表即时定位该停顿时间段；点击 5km 里程碑，图表定位到该里程节点。
- **区间框选空间下钻**：在折线图上滚轮缩放或框选冲刺段（如 15:00~20:00），左侧地图自动计算该段轨迹的空间包围盒，平滑调用 `fitBounds` 聚焦到具体街道。
- **特征极值一键跃迁**：点击“冲刺峰值 34.2 km/h”、“爬坡顶点 37 m”、“最长等灯 5.7 分钟”快速胶囊，秒级同步两端视野。

### 4. 4 款专业户外底图与坐标系自动投影校准
- 支持一键切换：
  - **☀️ 清新浅色**：高德矢量地图（GCJ-02 坐标，7px 深空蓝黑包边）。
  - **🌙 暗夜航道**：CARTO Dark（自动转 WGS-84，12px 激光天青霓虹光晕）。
  - **🛰️ 高清遥感**：高德卫星影像（纯白高光外边 + 柔和暗影底层，在深色建筑与森林中立体凸显）。
  - **⛰️ 等高地形**：OpenTopoMap（自动转 WGS-84，硬件栅格滤镜降噪 -45%，搭配 8.5px 高反差包边）。
- 提供**一键反转起终点方向**，满足折返路线或逆向记录的复盘需求。

### 5. 车手物理参数与 Agentic Memory 分层记忆流
- **物理档案与动力学**：录入体重、战车规格（如大行 P8 / 46T / 11-28T 7速 / 20寸406轮组）、右膝半月板劳损史与目标踏频区间（85-95 rpm）。
- **四层记忆架构**：
  - L1: 基础档案与生效目标。
  - L2: 长期原子事实画像（健康底线、机械调校、骑行偏好，单条不超过 35 字，去重合并）。
  - L3: 阶段目标演进里程碑（记录调优数值与变更依据）。
  - L4: 近期实战骑行与微观遥测。
- **防污染机制**：教练生成的目标计划写入独立里程碑表，杜绝大段课表文本污染长期事实库。

### 6. 数据安全与隐私脱敏
- 管理端支持划定家庭或公司隐私区域（设置经纬度与遮蔽半径）。
- 导入 GPX/TCX 轨迹时自动模糊敏感点位，保护日常起止点隐私。

## 项目架构与技术栈

本项目采用 Turborepo Monorepo 组织结构：

```
Cycling/
├── apps/
│   ├── web/               # 骑手分析工作台 (前端用户界面)
│   │   ├── src/
│   │   │   ├── components/  # 仪表盘、骑行详情、图表联动、记忆画像抽屉等
│   │   │   ├── pages/       # Dashboard, RideDetail, ActivitiesList, AICoach 等
│   │   │   └── utils/       # 遥测解算、坐标投影、卡路里与双均速计算公式
│   │   └── vite.config.ts
│   │
│   └── admin/             # 数据入库管理端
│       ├── src/
│       │   ├── components/  # GPX/TCX 文件解析、隐私圈绘制、AI 服务配置
│       │   └── utils/       # XML 轨迹点提取、多段距离聚合与过滤
│       └── vite.config.ts
│
├── packages/
│   └── api/               # 后端边缘 API 服务 (Cloudflare Workers / Hono)
│       ├── src/
│       │   ├── routes/      # 骑行数据存取、AI 复盘分析、教练对话、档案接口
│       │   ├── services/    # D1 SQLite 迁移、记忆分层装配、动力学计算
│       │   └── utils/       # 齿比踏频推演、物理功率估算
│       └── wrangler.jsonc
│
└── .handoffs/             # 阶段交接与架构备忘文档 (本地环境)
```

### 技术栈选型
- **Web 端**：React 19 + TypeScript + Vite 8 + Tailwind CSS + MapLibre GL + ECharts + Lucide Icons
- **Admin 端**：React 19 + TypeScript + Vite 8 + Turf.js + fast-xml-parser
- **API 端**：Cloudflare Workers (workerd) + Hono + D1 Database (SQLite) + OpenAI/DeepSeek 兼容客户端
- **包管理器**：`pnpm` (工作区单仓规范)

## 本地快速启动

### 前置要求
- Node.js >= 18.0.0
- pnpm >= 9.0.0

### 安装依赖
```bash
pnpm install
```

### 启动全部服务
```bash
pnpm dev
```

启动后各端本地访问地址如下：
- **骑手工作台 (Web)**: `http://localhost:5173`
- **数据管理端 (Admin)**: `http://localhost:5174`
- **后端 API 引擎 (API)**: `http://localhost:8787`

pnpm build

## 贡献与规范

1. **包管理器规范**：所有模块与脚本强制使用 `pnpm`，严禁使用 `npm` 或 `yarn`。
2. **坐标系转换约定**：任何涉及 OpenTopoMap 或 CARTO 的坐标绘制，必须调用 `adaptCoordinatesToMapStyle` 保证 WGS-84 正确投影。
3. **真实性原则**：所有界面展示的速度、海拔、停顿与爬升数据必须严格从真实 GPS 轨迹和码表指标中计算，杜绝任何人工合成波形。
